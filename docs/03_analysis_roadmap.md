# 03 分析流程与交付验收

## 阶段1：数据获取与来源核验

- 下载官方仓库中的四类数据文件和数据说明；
- 保存官方许可和字段文档链接；
- 记录数据文件哈希、大小和覆盖范围；
- 原始数据只读保存，不直接修改。

完成标准：能够列出每个文件的行数、字段、主键候选和业务粒度。

## 阶段2：数据质量检查

- 主键唯一性和重复记录；
- 时间字段缺失和先后顺序；
- 订单、运单、派单记录的基数关系；
- 经纬度、距离和异常值；
- 商圈、商家、骑手覆盖情况；
- 取消订单和无效订单的处理规则。

完成标准：形成数据质量报告，并明确哪些记录进入主要分析样本。

## 阶段3：订单级分析宽表

- 选择订单或运单作为事实粒度；
- 聚合一对多派单尝试，避免关联后重复；
- 生成履约阶段时长、是否超时、空间距离、商圈和时段字段；
- 通过行数、去重订单数和金额无关的控制总量进行核对。

完成标准：每行代表一个明确的业务事实，所有衍生字段可追溯。

## 阶段4：履约经营诊断

- 全局指标基线；
- 日期和小时趋势；
- 商圈×时段二维定位；
- 订单规模与超时率联合分层；
- 履约阶段拆解；
- 骑手供需压力和超时关系；
- 形成问题商圈画像与初步运营建议。

完成标准：每项建议都能对应明确的问题人群、指标和可执行动作。

## 阶段5：订单超时风险模型

- 定义预测时点；
- 仅使用预测时点可获得的特征；
- 建立仅按配送距离排序的业务基线；
- 训练直方图梯度提升分类器；
- 使用按日期划分的跨期留出验证；
- 输出Top-K覆盖率、Lift和特征解释。

完成标准：模型结果能够转化为订单或商圈时段的处理优先级。

## 阶段6：高峰期运力配置

- 以官方派单快照为时间单位，构造 500 米 × 400 米需求网格；
- 以网格中心 2 公里范围候选骑手数作为局部供给可达性指标；
- 设置每快照 10、20、30、50 个假设增量运力槽位；
- 对比按等待订单量分配和风险加权供需分配；
- 进行历史回放并报告护栏指标。

完成标准：方案包含投入对象、时点、预算、优先级、集中度护栏和适用边界。

## 阶段7：项目交付

- 经营分析报告或仪表盘；
- 可复现SQL和Python代码；
- 项目 README 与复现说明；
- 管理层业务报告与方法附录；
- 对项目限制和未验证结论的说明。
