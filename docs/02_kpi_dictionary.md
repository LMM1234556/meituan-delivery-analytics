# 02 指标字典

## 1. 使用原则

1. 先核验原始字段含义和时间戳顺序，再正式冻结指标口径；
2. 所有比率都必须明确分母和有效订单范围；
3. 订单、运单和派单记录存在一对多风险，订单级指标必须先去重；
4. 平均值与 P50、P90 同时报告，避免长尾超时被平均值掩盖；
5. 当前不设人工目标值，先计算历史基线和分布。

## 2. 核心结果指标

### 2.1 订单准时率 `on_time_rate`

定义：有效完成订单中，实际送达时间不晚于预计送达时间的订单占比。

公式：

```text
COUNT(DISTINCT CASE WHEN arrive_time <= estimate_arrived_time THEN order_id END)
/
COUNT(DISTINCT valid_completed_order_id)
```

用途：衡量平台是否兑现面向用户的时间承诺，是项目的主要结果指标。

主要限制：必须排除取消、无实际送达时间、无预计送达时间及明显异常时间戳的订单。

### 2.2 超时订单数 `late_order_count`

定义：实际送达时间晚于预计送达时间的有效完成订单数。

用途：衡量问题规模。超时率相同的情况下，应优先关注超时订单绝对数量更大的商圈时段。

### 2.3 超时分钟数 `late_minutes`

定义：

```text
MAX(0, arrive_time - estimate_arrived_time)
```

报告：均值、P50、P90。

用途：区分轻微超时和严重超时。

## 3. 履约过程指标

### 3.1 总履约时长 `total_fulfillment_minutes`

定义：平台下单至实际送达的分钟数。

```text
arrive_time - platform_order_time
```

### 3.2 平台处理时长 `order_push_minutes`

定义：平台下单至订单进入配送流程的分钟数。

```text
order_push_time - platform_order_time
```

### 3.3 进入配送至接单时长 `order_push_to_accept_minutes`

定义：订单派出至骑手接单的分钟数。

```text
grab_time - order_push_time
```

口径：订单进入配送系统至最终成功接单；多次派单产生的摩擦通过运单尝试次数、拒绝次数和首次/最终派单等待单独保留。

### 3.4 接单至取餐时长 `accept_to_pickup_minutes`

定义：骑手接单至完成取餐的分钟数。

```text
fetch_time - grab_time
```

限制：这一阶段可能同时包含骑手前往商家的时间和到店等待时间。如果没有骑手到店时间，不能直接称为“商家出餐等待时长”。

### 3.5 取餐至送达时长 `pickup_to_delivery_minutes`

定义：完成取餐至实际送达的分钟数。

```text
arrive_time - fetch_time
```

用途：反映最后一公里配送阶段的时效。

## 4. 需求与运力指标

### 4.1 等待派单订单数 `waiting_orders`

定义：官方派单决策时点内、落在指定 500 米 × 400 米商家网格的待派订单数。

用途：衡量快照时点的局部即时需求。该指标来自 `dispatch_waybill`，不使用订单完成后的结果字段。

### 4.2 两公里候选骑手数 `candidate_riders_within_2km`

定义：以需求网格中心为圆心，两公里范围内的候选骑手去重数。

用途：衡量网格周边的局部供给可达性。

限制：候选骑手不等于可立即调动的空闲骑手；相邻网格邻域重叠，因此不可跨网格求和解释为全城独立供给人数。

### 4.3 零在手单候选骑手数 `idle_candidate_riders_within_2km`

定义：两公里范围内 `courier_waybills` 列表为空的候选骑手数。

用途：作为局部供给状态的辅助指标。

限制：零在手单骑手可能处于在线休息状态，不等同于确定可用运力。

### 4.4 等待订单压力 `waiting_orders_per_candidate_2km`

```text
waiting_orders / max(candidate_riders_within_2km, 1)
```

用途：比较不同网格在同一派单快照中的相对供需压力，不用于估算真实缺口人数。

## 5. 空间与订单复杂度指标

### 5.1 商家至用户直线距离 `merchant_customer_distance`

定义：根据脱敏经纬度使用 Haversine 公式计算的相对直线距离。

限制：不代表真实道路距离，也不用于恢复真实地点。

### 5.2 接单点至商家距离 `courier_merchant_distance_at_accept`

用途：判断骑手接单后前往商家的空间成本。

口径：使用成功运单记录的接单时骑手坐标与商家坐标计算。

## 6. 模型评估指标

不把 Accuracy 作为主要指标，优先使用：

- PR-AUC：适合超时样本占比较低的情况；
- Recall@Top 10%：最高风险10%订单覆盖了多少实际超时订单；
- Lift@Top 10%：最高风险10%订单的超时率相对全体提升多少；
- 分商圈、分时段Recall：检查模型是否只在大商圈有效；
- 跨期稳定性：不同留出日期之间的结果波动。

## 7. 策略结果与护栏

### 7.1 等待订单覆盖率 `waiting_order_coverage_pct`

定义：被分配至少一个运力槽位的网格所覆盖的等待订单数，占全部回放快照等待订单数的比例。

### 7.2 预期超时风险覆盖率 `expected_late_risk_coverage_pct`

定义：被配置网格中的预测超时概率之和，占全部网格预测超时概率之和的比例；不可评分订单使用历史平滑超时率补充。

### 7.3 后验超时订单覆盖率 `actual_late_order_coverage_pct_hindsight`

定义：被配置网格中后续实际超时订单数，占全部回放快照实际超时订单数的比例。

限制：该指标只验证配置规则是否更集中地识别后续超时订单，不代表策略减少了相同比例的超时订单。

### 7.4 单网格配置占比 `max_single_grid_allocation_share_pct`

定义：单个快照内，获得槽位最多的网格占该快照总预算的比例。

护栏：单网格槽位数不超过 `ceil(当次预算 × 25%)`。预算无法被 4 整除时，实际占比可略高于 25%。

### 7.5 假设增量运力槽位 `rider_slot`

定义：某派单快照中分配给一个网格的一单位假设资源预算。

限制：运力槽位不等同于骑手人数、骑手工时、排班成本或已执行调度量。
