# 07 午高峰骑手运力优先级情景

## 1. 决策对象

城市履约运营负责人需要在午高峰派单时点和给定增量运力预算约束下，确定可调度运力的空间配置优先级。

公开数据仅提供 8 天内每天 3 个午高峰派单快照。本情景使用 2022-10-23 和 2022-10-24 共 6 个跨期快照进行回放，不能外推为全天或长期配置策略。

## 2. 分析单位

- 空间单元：500 米（东西）× 400 米（南北）的脱敏坐标网格；
- 时间单元：一个官方调度决策时点；
- 需求：快照中等待派单的订单，按商家位置落网格；
- 供给：商家网格中心 2 公里范围内的候选骑手数；
- 闲置候选：`courier_waybills` 为空的候选骑手，仅作为辅助指标。

候选骑手不等于可立即调动骑手。官方论文指出，部分零在手单骑手可能在线休息，因此不能把全部闲置候选都当作确定供给。

相邻网格的 2 公里邻域会重叠，同一骑手可能同时被多个网格计入。因此该字段是局部可达性指标，不能跨网格求和解释为全城独立供给人数。

## 3. 配置前可用信息

每个快照只能使用：

- 当前等待订单数；
- 当前 2 公里范围候选骑手数；
- 当前闲置候选骑手数；
- 2022-10-17 至 2022-10-22 训练的订单进入配送时风险模型（用于 10 月 23–24 日符合模型样本定义的订单）；
- 对预订单或未知商圈订单，回退到该网格在快照日期之前的历史超时率。

历史超时率使用 50 单强度的贝叶斯平滑：

```text
smoothed_late_rate = (grid_late_orders + 50 × prior_global_late_rate)
                     / (grid_orders + 50)
expected_late_demand = 可评分订单的模型风险概率之和
                     + 不可评分订单数 × smoothed_late_rate
```

模型概率未经过独立的长期校准，因此概率之和仅作为相对风险质量参与排序，不解释为可直接兑现的超时订单绝对预测值。

实际是否超时只用于回放后的后验评估，不进入配置规则。

## 4. 两种策略

### 4.1 风险加权供需策略

逐个分配增量运力槽位，每次选择：

```text
expected_late_demand / (nearby_candidate_riders + already_allocated + 1)
```

最高的网格。分母随配置增加，形成边际收益递减。单网格槽位上限为 `ceil(当次预算 × 25%)`；预算无法被 4 整除时，实际最大占比会略高于 25%。

### 4.2 订单量供需基线

逐个分配增量运力槽位，每次选择：

```text
waiting_orders / (nearby_candidate_riders + already_allocated + 1)
```

最高的网格。用于判断加入模型和历史履约风险是否改变配置优先级。该基线使用相同的单网格槽位上限。

## 5. 预算情景

每个快照分别模拟 10、20、30、50 个增量运力槽位。该参数仅用于预算敏感性分析，不代表已确认排班预算，也不能直接换算为骑手工时。

## 6. 回放指标

- 被配置网格覆盖的等待订单占比；
- 被配置网格覆盖的预期超时风险占比；
- 被配置网格覆盖的实际超时订单占比（仅后验验证）；
- 按分配槽位加权的实际超时率；
- 单网格最大配置占比，作为集中度护栏。

## 7. 适用边界

- 公开数据没有运力干预的因果响应函数，因此回放不估算“可减少的超时订单数”；
- 候选骑手数仅表示局部供给可达性，不等同于真实排班人数或在线可调动人数；
- 脱敏网格不映射为真实商圈和地址；
- 六个午高峰快照仅用于短周期离线验证，不代表长期稳定收益。
