# 06 超时风险模型设计

## 1. 模型定位与使用场景

模型用于在订单完成前排序风险，帮助运营把有限关注和干预资源放在高风险订单及其聚集的商圈时段。它不替代履约诊断，也不直接证明增加运力的因果效果。

## 2. 两个预测时点

### 2.1 订单进入配送系统时 `push_time_model`

可用信息：

- 匿名商圈；
- 订单进入配送系统的小时、星期和是否周末；
- 商家至用户直线距离；
- 承诺履约分钟数；
- 下单至进入配送系统时长。

用途：更早进行风险预警和商圈时段风险汇总。

### 2.2 骑手接单时 `acceptance_time_model`

在上述特征基础上增加：

- 运单尝试次数、已拒绝次数；
- 首次/最终派单等待；
- 最终派单至接单时长；
- 接单点至商家直线距离。

用途：支持接单后的订单级风险分层与履约跟进。该模型对应更晚的运营处置时点，但能够观察已经发生的派单摩擦。

## 3. 明确禁止的泄漏特征

以下字段在预测时点尚未发生或由结果定义，禁止进入模型：

- `fetch_time`、`arrive_time`、`late_minutes`、`is_late` 之外的任何标签变形；
- 接单至取餐、取餐至送达、总履约时长；
- 波次最终订单数，因为它包含该波次之后才接到的订单；
- 测试日期计算出的商家或骑手历史超时率；
- 随机切分后从同一时间窗口泄漏的未来聚合特征。

## 4. 数据切分

- 训练候选模型：2022-10-17 至 2022-10-21；
- 验证：2022-10-22；
- 最终训练：2022-10-17 至 2022-10-22；
- 跨期测试：2022-10-23 至 2022-10-24。

仅有 8 天数据，因此测试结果仅反映短周期跨期稳定性，不代表长期泛化能力。

## 5. 模型与评估

模型：直方图梯度提升分类器。类别字段使用训练期类别集合，测试期新类别按未知值处理。

主要指标：

- PR-AUC：评价不平衡标签下的整体排序；
- ROC-AUC：补充区分能力；
- Recall@Top10%：最高风险 10% 订单覆盖多少实际超时；
- Lift@Top10%：最高风险 10% 的超时率是总体的多少倍；
- Brier score：检查概率误差。

不把 Accuracy 作为主要指标，因为全预测为准时也会得到较高准确率。

## 6. 解释边界

特征重要性表示模型对排序性能的依赖，不等于该特征导致超时。距离、承诺时长、商圈和派单摩擦可能共同受未观察到的订单复杂度、道路、天气和平台策略影响。
